# 咖啡馆 · 咖啡豆批次与饮品出单

咖啡馆经营管理系统：咖啡豆批次烘焙状态机、饮品菜单、桌台开台/清洁、收银台一条式点单出单（POS）。

## 技术栈

- 后端：Spring Boot 3.3 + Spring Data JPA + MySQL
- 前端：Vue 3 + Element Plus（顶部横向导航、棕色主题）

## 启动

```bash
sh start.sh        # 构建并启动（首次较慢，之后秒级）
sh stop.sh         # 停止
```

启动后访问前端地址（默认 http://127.0.0.1:8312 ）。

## 业务模块

1. **咖啡豆批次**：批次号唯一，烘焙状态机 待烘焙→烘焙中→已入库→已用完，只能逐级前进；标记入库时按重量生成批次余量（克）与入库时间，入库后批次信息锁定。
2. **饮品菜单 + 配方**：名称唯一，价格>0，类别（意式/手冲/非咖啡），状态（在售/下架）；管理员可在「维护配方」中维护每杯所需豆种（按批次产地匹配）与克数，支持拼配多豆种。非咖啡类无配方、不耗豆。
3. **桌台**：桌号唯一，座位数>0，状态（空闲/占用/清洁中）；仅空闲可开台，状态只能由开台/结账/完成清洁驱动，不能手工改。
4. **收银出单（豆量闭环）**：左选饮品→中点单流水→右结算；同一桌台仅允许一张未结账账单；账单状态机 制作中→已完成→已结账，结账后释放桌台。
   - 点单时库存不足的饮品会明确提示（仍可点单）；
   - 完成制作必须选择操作者，系统按**当时保存的配方**汇总豆量，只从「已入库且有余量」批次中按入库时间 FIFO 自动分配，单一批次不足自动跨批次拆分；
   - 整张账单必须全量满足才扣减：任一豆种不足或缺配方，则事务整体回滚，账单保持「制作中」、任何批次一克不扣；
   - 扣减与消耗流水（批次、批次号、豆种、饮品、克数、操作者、时间）在同一事务写入，账单行锁防重复推进，批次行锁（主键顺序）防超扣、防死锁；
   - 金额取点单时的菜名/单价快照，消耗流水固化批次与豆种——事后改菜单价、改配方都不影响历史账单；
   - 批次页「消耗追溯」可查某批次被哪些账单（含桌号）、饮品、操作者在何时消耗。
5. **桌台清洁交接（结账→清洁→再开台闭环）**：
   - 结账不再直接把桌台置空闲：结账同事务内桌台「占用→清洁中」，生成「待接单」清洁单与「结账转清洁」流水（记录结账收银员）；
   - 清洁人员**接单**时记录责任人、开始时间、预计完成时间（待接单→清洁中）；清洁中可多次**暂存未完成原因**，刷新页面后责任人/时间/原因仍在；
   - **完成清洁**后桌台才回到「空闲」可开台；清洁中可**撤回清洁**（回待接单、责任人清空、未完成原因保留，异常中断后下一位可继续）；
   - 收银员不能绕过清洁开台（桌台行锁拦截并提示责任人/进度）；桌台已有下一桌新账单时，旧清洁单的接单/完成/撤回全部被拦截，不能把已有新账单的桌台重新标记为清洁中；
   - 并发点击完成清洁、撤回清洁、开台：清洁单行锁 + 桌台行锁串行，只接受一个合法状态推进，失败操作回滚，不覆盖最新责任人与原因；
   - 交接流水（cleaning_log）只追加不改写，后续清洁或再次开台都不会改写历史；管理员可看当前清洁队列与最近交接记录。

## 关键接口

- `GET /api/stock/on-sale`：在售饮品单杯库存（点单提示）
- `GET/PUT /api/menu-items/{id}/recipe`：配方查询/全量保存（只含豆种+克数，无批次字段）
- `GET /api/order-tickets/{id}/finish-preview`：完成前消耗预演（FIFO 拆分、缺口原因）
- `POST /api/order-tickets/{id}/finish`：完成制作（body 带 `operator`）
- `POST /api/order-tickets/{id}/settle`：结账（body 带 `operator`，结账后桌台进清洁队列）
- `GET /api/cleanings/queue`：当前清洁队列（待接单+清洁中，附责任人/时间/未完成原因/拦截状态）
- `POST /api/cleanings/{id}/claim|save-reason|complete|withdraw`：清洁人员接单/暂存原因/完成/撤回
- `GET /api/cleanings/dashboard`：管理员看板（当前队列 + 最近 50 条交接流水）
- `GET /api/cleanings/{id}/logs`、`GET /api/cleanings/table/{tableId}/logs`：清洁单/按桌台的历史交接记录
- `GET /api/stock/bean-batches/{id}/trace`：批次消耗追溯
